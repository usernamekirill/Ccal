# NLP / QA отчёт CalorieBot

Дата: 2026-04-30. Работа в существующей архитектуре (без переписывания БД и публичных контрактов сервисов).

## Найденные баги

1. **Нет единой нормализации до парсинга** — строки вида `гречка200г` и лишние пробелы ухудшали извлечение граммов в цепочке LLM + `apply_user_gram_priority`.
2. **Падежи продуктов** (`риса`, `шарлотки`, `курицы`) не приводились к номинативу в офлайн-парсере — ухудшало кэш и отображение.
3. **Нет быстрого пути без LLM** для типичной одной порции — при сбое API пользователь получал отказ даже при корректном тексте.
4. **Сообщения об ошибках** содержали формулировку «не получилось уверенно распознать» в `texts.py` и `errors.py` — против продуктовых требований (нужны уточнение или честный сбой сервиса).
5. **Кейсы без единиц** (`гречка 200`, только `200 г`) не переводились в явное уточнение до превью.

## Что улучшено для пользователя

- Базовые фразы с граммами разбираются **до вызова LLM**, быстрее и устойчивее к сбоям API.
- Ошибочные/неполные массы дают **явное уточнение**, а не только общий отказ.
- Единая нормализация для **текста и приоритета граммов** после LLM.

## Что остилось (вне этого PR)

- Полная **лемматизация** (pymorphy и т.д.) — не подключалась, чтобы не раздувать зависимости; используется **ограниченный словарь** падежей.
- **Разбиение нескольких продуктов без LLM** (`яблоко банан`, составные блюда) по-прежнему опирается на модель и промпты — отдельный rule-based splitter возможен позже.
- **Vision**: много блюд на фото, сверка total — требует сценарных тестов на моках `AIPhotoService` (не добавлялось).
- **Статистика**: пересчёт при удалении/редактировании — покрывается существующими тестами синка; отдельный e2e не расширялся.
